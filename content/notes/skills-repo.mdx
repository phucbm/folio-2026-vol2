[phucbm/skills](https://github.com/phucbm/skills) is where I keep what I learn on real projects, written for an agent instead of for me. Each skill is one `SKILL.md`: when to use it, the steps, the gotchas. The next project installs it and the agent follows it, so I don't explain the same thing again. I started it because I kept explaining the same setup to Claude in every new project.

## Install

The repo works with the skills CLI and as a Claude Code plugin marketplace:

```shell
npx skills@latest add phucbm/skills
/plugin marketplace add phucbm/skills
/plugin install skills@phucbm
```

## How a skill gets in

Three skills maintain the repo itself. `add-skill` writes a new one from what the current project just did, `update-skill` changes an existing one with a diff first, and `learn` scans a repo I am visiting and lists what is worth saving. All three show the file and wait before pushing: an agent writing into my own knowledge base without asking is the one thing I didn't want.

Two rules came from using it. A skill is generic, and a project appears only as an example, never as a fact. And everything goes in the one `SKILL.md`; the first version split skills into a thin wrapper plus shared "knowledge" files; one file per skill is simpler to keep up to date.
